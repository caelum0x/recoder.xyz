# Gemini Interaction Customization (`GEMINI.md`)

This file customizes how the Gemini AI assistant interacts with the CodeCraft project. It is based on the information found in `README-AI-INTEGRATION.md`, `SETUP.md`, and `structure.md`.

## 1. Architecture & Structure

The project is a TypeScript monorepo managed with **Nx**. The structure is as follows:

- **`backend/`**: The main API server built with **Node.js**, **Express**, and **Prisma** for database access. It handles business logic, user authentication, and AI model integration.
- **`packages/`**: A collection of workspaces, including:
    - **`cli/`**: The command-line interface (`@codecraft/cli`) built with **TypeScript** and **Commander.js**. This is the primary tool for interacting with the system.
    - **`web/`**: A web-based dashboard built with **Next.js** and **React**.
    - **`shared/`**: Shared utilities, types, and constants used across different packages.
    - **`vscode-extension/`**: A VS Code extension for IDE integration.
- **`production-engine/`**: A dedicated engine for generating and validating production-ready code.
- **`scripts/`**: Contains scripts for building, testing, and setting up the project.
- **`docs/`**: Project documentation.
- **`examples/`**: Contains real-world example projects.

## 3. AI Integration

The project features a sophisticated **AI Model Integration Hub** with the following characteristics:

- **Multi-Provider Support**: Integrates with both cloud-based AI models (OpenAI, Anthropic, Google, etc.) and local models via **Ollama**.
- **Intelligent Routing**: Automatically selects the best model based on the task, privacy requirements, and performance.
- **Privacy-First**: Prioritizes local models for sensitive data and supports different privacy levels (Public, Internal, Confidential, Restricted).
- **Advanced Capabilities**: Includes context-aware processing, hybrid model processing, and detailed monitoring/analytics.
- **Specialized Agents**: The system uses various specialized agents for tasks like planning, web development, mobile development, blockchain, and more.

## 4. Development Workflow

- **Setup**: The project can be set up by running `node scripts/setup.js` or `npm install` followed by `npm run build`.
- **Development**:
    - `npm run dev`: Starts all development servers.
    - `npm run dev:<package>`: Starts the development server for a specific package.
- **Building**:
    - `npm run build`: Builds all packages.
    - `npm run build:<package>`: Builds a specific package.
- **Testing**:
    - `npm run test`: Runs all tests.
    - `npm run test:<package>`: Runs tests for a specific package.
- **Linting & Formatting**:
    - `npm run lint`: Lints all packages.
    - `npm run format`: Formats the codebase with Prettier.

## 5. Key Processes

The project follows a structured process for code generation and validation:

1.  **Planning**: A dedicated planning phase (`project-planner.js`, `feature-planner.js`, etc.) is used to define the architecture and requirements before implementation.
2.  **Analysis**: The system includes various analyzers (`requirement-analyzer.js`, `dependency-analyzer.js`, etc.) to understand the project context.
3.  **Generation**: Code is generated by specialized generators (`web-generator.js`, `blockchain-generator.js`, etc.) that aim to produce production-ready code.
4.  **Integration**: The system ensures that different parts of the application are correctly connected and functional.
5.  **Validation**: A validation system (`code-validator.js`, `integration-validator.js`, etc.) is used to verify that the generated code works as expected.
