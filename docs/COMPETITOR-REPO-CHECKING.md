# How Competitors Check Open-Source Repositories — Competitive Analysis

> Generated 2026-08-18 by a 17-agent research workflow (web research + OSS repo study across 14 competitors),
> then mapped against Recoder's convergence / Checks / merge-readiness surface. Sources cited per competitor.

## Landscape summary

The field splits into three camps. (1) PR-review bots (CodeRabbit, Greptile, Devin, Cursor Bugbot, Graphite Diamond, Baz, Ellipsis, Qodo, Sweep, Copilot) ingest the diff plus repo context, emit line-level findings, and filter false positives. (2) Coding-agent substrates own repository intelligence without acting as merge gates. (3) Orchestrators and merge platforms gate integration. Recoder combines these shapes in the installed app: selected runtimes produce evidence-required findings, symbol and defect anchors form named K/N agreement, and a separate judge Session returns confirmed, rejected, or uncertain evidence before the human publishes. RecoderGit adds bounded upstream, downstream, test, process, depth, and risk evidence when its graph is present. Repositories can run bounded deterministic argv checks locally or off-box, and configured stdio LSP servers produce base-versus-head diagnostic deltas. A deterministic diff scanner hard-blocks redacted secret findings and added package lifecycle hooks, while new/non-registry dependencies and oversized lockfile churn become visible review advisories. The remaining deterministic gap is full SAST and vulnerability/license intelligence; the watcher also publishes no advisory GitHub status check.

## Competitor matrix (ingestion — key checks — merge gate)

- conductor.build (Melty) — no own index, delegates all code understanding to Claude Code/Codex CLIs in git worktrees — Checks tab aggregates git/PR/CI/deploy/comment/todo state — human 4-item checklist gate, no auto-merge, no trust score
- Cursor Bugbot — diff-first + dynamic agentic context-pulling (Rust git integration, no clone), upward-traversing .cursor/BUGBOT.md rules — semantic logic/cross-file/security bugs, dedicated false-positive validator model, resolution-rate metric — advisory-by-default GitHub status check (success/neutral/failure), fail-on-unresolved opt-in
- Devin Review + DeepWiki — code-to-code knowledge graph (call/symbol/co-modification) + vector RAG shared with the agent; PR path is lighter git-diff worktree — severity x confidence bug/security tiers, semantic hunk grouping, move/copy detection, line-level citations — advisory CI check, human-review recommended, closed autofix loop with no independent fix verification
- CodeRabbit — per-PR disposable microVM full clone: fresh code graph + persistent embeddings + ast-grep, agent explores via raw shell — 50+ linters/SAST (Semgrep/Gitleaks/Checkov), blast-radius, runs build+tests, evidence-script-gated findings — two-tier pre-merge checks (off/warning/error) + Request-Changes review = hard gate via branch protection
- Greptile — persistent code graph: tree-sitter AST -> NL-docstring-per-node embeddings + hybrid agentic retrieval walking call edges — 0-5 merge-readiness score, P0/P1/P2 severity, multi-hop cross-file, learned rules — advisory 0-5 score; hard blocking delegated to host branch protection
- Qodo Merge / PR-Agent (OSS) — diff-centric, token-aware adaptive patch compression, NO index; injects AGENTS.md/best_practices/checklist as text — structured YAML: effort 1-5, 0-100 score, security/tests/ticket-compliance, self-reflection re-scoring — OSS advisory (self-review checkbox cosmetic); commercial adds blocking compliance gate + auto-approval
- Sweep (OSS) — full clone, hybrid per-run index: tree-sitter chunks + Tantivy BM25 + embeddings + networkx import graph + rerank — 5-pass group-vote (>=4/5 = issue, 3/5 = potential), new-vs-old lint diff, duplicate-utility, edge-case Q&A — advisory single PR comment, self-consistency vote is the quality gate, no auto-merge
- Aider (OSS) — git-native whole-repo tree-sitter tag map + personalized PageRank, mtime-keyed SQLite cache, no embeddings — tree-sitter syntax + py_compile + FATAL-ONLY flake8 (E9/F821) + user lint/test cmd — no merge gate; bounded reflection loop (max 3) + per-edit auto-commit as undo surface
- Continue (OSS) — local four-index fusion (LanceDB vectors + FTS5 + tree-sitter snippets + repo-map), per-branch IndexTag incremental — markdown check/agent specs: security-audit, anti-slop, stale-comments, breaking-change, test-coverage, dep-security — GitHub Actions matrix; each check a native Check Run (pass/fail); checks autofix-commit, agents advisory
- opencode (OSS) — no index; on-demand ripgrep/glob/read + LIVE LSP (hover/refs/callHierarchy) + shadow-git snapshot via objects/info/alternates — post-edit LSP diagnostics loop (ERROR-only, cap 20) + format-on-write + permission gate — no merge/verification gate at all; substrate only, gating delegated to GitHub
- GitHub Copilot code review — agentic ephemeral Actions env + internal Code Graph, reads copilot-instructions/AGENTS.md, MCP tools — logic/security/style (LLM, no bundled deterministic linters), cross-service at higher effort, dedup — advisory ONLY: always 'Comment', never approve/request-changes, cannot satisfy branch protection
- Graphite Diamond + Merge Queue — codebase-aware (AST parse + repo context; retrieval method undisclosed), glob-injected rule files — logic/security/perf/consistency, multi-layer voting+self-critique, sub-3% FP (lowest recall ~18%) — SPLIT: Diamond advisory co-reviewer; Merge Queue is the real gate (trial rebase + real CI, eject-with-reason)
- Baz — whole-repo indexable units + embeddings retrieval, Difftastic/tree-sitter semantic AST diff, cross-repo consumer refs, prod telemetry — roster of single-concern reviewers (breaking-change/type/logic/spec/security/SRE), evidence-gated, runtime browser spec-check, blast-radius — autonomous Merger: merge/reject/ESCALATE via deterministic bars + NL guideline; escalate = human safety valve
- Ellipsis — fresh incremental Turbopuffer index keyed by chunk SHA (tree-sitter chunks + per-file LLM summaries) + lsproxy LSP sidecar — dozens of parallel comment-generators, evidence-anchored, multistage filter: dedup + confidence threshold + hallucination check — advisory-by-default incremental review; optional auto-approve; hard block via branch protection

## Biggest gaps (Recoder vs the field)

1. **Closed for the installed-app loop 2026-08-30:** Recoder produces evidence-required, line-anchored findings, makes each anchor navigable at the exact reviewed head SHA, lets a human select/edit findings into one head-bound native GitHub review, embeds stable finding identity in each inline comment, and re-joins GitHub-authoritative open/resolved/outdated thread state after restarts and pushes. Deterministic symbol + defect-class identity clusters shifted-line reports and follows real diff renames without message-similarity guessing. A fresh role-isolated validator Session now judges the complete cohort's canonical findings as confirmed/rejected/uncertain with evidence before human publication.

2. **Mostly closed 2026-08-31:** repository-owned explicit argv checks can run locally or opt into an ephemeral off-box sandbox with bounded tracked-delta sync. `.recoder/lsp.json` drives real stdio LSP servers over changed files, and Wave shows introduced/resolved base-versus-head diagnostics. Remaining: broader automatic analyzers and provider artifact upload for deltas larger than the bounded patch transport.

3. **Closed for the installed-app review loop 2026-08-30:** selected installed runtimes review the same PR revision independently; evidence-less/malformed findings are dropped and deterministic file + symbol + defect-class clusters surface as K/N with named reviewer sources even when line anchors shift. Different symbols remain separate. Recoder deliberately exposes observed agreement rather than an invented confidence score. Repo-scoped Accept/Dismiss decisions persist and feed later reviewer prompts.

4. **Closed for repository-scoped explicit feedback 2026-08-30:** Wave records durable repo-scoped Accept/Dismiss rules for PR findings and convergence trust flags. PR rules use qualified symbol + defect class; convergence rules use the normalized exact evidence flag. Successful composed deliveries remain “proceeded with,” never an implicit disposition. Wave exposes Accept risk / Dismiss noise / Restore controls after delivery. Each governed click updates the active rule and a bounded append-only history. Accepted trust flags stay visible and add a small bounded confirmed-risk deduction; dismissed exact repeats are suppressed without restoring evidence points or erasing their underlying trust factor. Both profiles survive restart and remain auditable.

5. **Partially closed 2026-08-30:** Recoder deterministically scans diff-added lines for high-signal secrets with redacted evidence and hard-blocks newly added `preinstall`, `install`, and `postinstall` hooks. New registry/non-registry dependencies and lockfile additions over 500 lines surface as human-review advisories in readiness and Wave. Remaining: full SAST, native-binary detection, vulnerability and license intelligence for changed dependencies, and isolated execution for external analyzers.

6. **Closed for the installed review loop 2026-08-30:** the review loop queries both directions with test inclusion and a depth-three bound. It preserves risk, minimum depth, relation types, affected files, tests, process paths, directionless co-change history, and cross-repository consumers through reviewer, validator, fixer, Wave, the human review draft, and Conductor readiness. The packaged MIT graph confirms imported calls against target declarations across TypeScript/JavaScript, Python, Go, and Rust. Exact executable, server, worker, and route entrypoints provide process membership. RecoderGit scans up to 500 commits and records repeated file pairs with commit count and Jaccard confidence. During workspace indexing, RecoderGit matches provider packages to exact consumer files across npm, Python, Go, and Cargo repositories. Unsupported syntax retains file-import evidence and labels the combined result as mixed or file scope.

7. **Partially closed 2026-08-30:** Recoder now has a standing installed-app PR review state machine. It polls open PRs through the authenticated local `gh`, dedupes canonical review workspaces per repo/number/head SHA/runtime, and launches fresh independent review Sessions after a new push. Wave folds their structured evidence into named K/N finding clusters, compares adjacent revisions as new/persisting/fixed, and can prefill a human review. A finding is called fixed only after the full new reviewer cohort reports. Each current finding can also launch an idempotent fix Session from the exact reviewed commit; the row tracks its state and opens Wave's diff when the fix needs comparison. GitHub delivery remains human-owned: after governance/approval, Wave can publish a native Comment / Approve / Request changes review and selected canonical findings as inline comments bound to the reviewed head SHA. Stable hidden finding keys and GraphQL thread reads synchronize open/resolved/outdated state back into Wave. Residual gap: a native GitHub status check from the watcher.

8. **Mostly closed 2026-08-31:** the validator resolves explicit GitHub, Beads, and Jira requirements through canonical read-only ports and retains unavailable references as unknown evidence. JSON rules may bind exact named checks whose result cannot be overridden by the model. A durable Wave-owned Off/Warn/Block policy decides whether fresh required check-backed failures affect convergence trust, and convergence-evidence v4 seals that policy and its outcomes. Open-work detection itself remains regex/checkbox based.

9. **Partially closed 2026-08-30:** RecoderGit index state, the multi-repository package registry, and a compact versioned packaged graph snapshot persist through the installed app's canonical KV. Freshness, repo identity, stats, symbol calls, process nodes, co-change edges, external imports, package identities, and file impact survive a matching backend restart without a source scan. A changed tracked diff or untracked file content changes the source revision and rebuilds the graph. The trust gate remains non-blocking by default (`RECODER_MERGE_TRUST_GATE=warn`), so a low-trust merge receives an advisory unless an operator selects `block`.

## Ranked recommendations

### [SHIPPED] Cross-candidate self-consistency vote: turn Recoder's N real worktree agents into a finding-agreement signal
**Shipped for installed-app PR reviews 2026-08-30:** Wave launches selected real runtimes independently and renders deterministic file + qualified-symbol + defect-class agreement as K/N with named reviewer sources. Shifted lines and real diff renames retain identity; different symbols and vague message similarity never collapse.
**Why it matters:** Sweep and Ellipsis had to re-sample one reviewer to fabricate N-way agreement; Recoder votes across genuinely independent installed-agent executions and exposes observed counts rather than an invented confidence score.
**Where in Recoder:** `backend/src/domains/agent-os/services/pr-review-findings.service.ts` and `apps/desktop/app/frontend/app/view/recoder/recoder-pr-review-agents.tsx`.

### [SHIPPED] Make the 'checks' signal run Recoder's own checks in a sandbox (tests/typecheck/lint/build + LSP-diagnostics delta), not just mirror GitHub
**Shipped:** `.recoder/checks.json` supplies bounded explicit argv checks. Their pass/fail/error results fold alongside GitHub, hard-block on failure, and render as named Recoder rows in Wave even without a PR. Concurrent detailed/readiness consumers share one execution.
**Shipped next:** a repo can mark a named check `autofix: true` (plus an optional bounded `fixPrompt`). Wave labels the capability and, on a real failure, lets the operator ask the installed runtime to remediate the exact argv-backed check in the same isolated Session/worktree through a dedicated governed edge. Recoder reproduces the failure before launch and independently reruns the exact named argv after the agent settles; durable attempt evidence drives `fix running / verified / still failing / unverified` rows. Checks without that explicit bit remain manual advisories.
**Shipped 2026-08-31:** `execution:"offbox"` provisions the existing cloud sandbox, clones the base, applies the bounded tracked binary delta, runs exact preparation/check argv, and tears down. `.recoder/lsp.json` launches real stdio servers and compares each changed file's base and head buffers against one project root. Wave renders the introduced/resolved rail; unavailable servers never fabricate a clean result.
**Where in Recoder:** `backend/src/domains/conductor/adapters/check-runner.adapter.ts`, `services/check-run.service.ts`, `services/pr-checks.service.ts`, `services/readiness.service.ts`, and the Wave Review Checks strip.

### [SHIPPED] Upgrade the advisory auto-review from a blast-radius count to real, evidence-gated line-level findings with a false-positive validator pass
**Shipped for installed-app PR reviews 2026-08-30:** Every reviewer emits a structured, line-anchored evidence contract. After the full cohort reports, one fresh role-isolated validator Session independently checks the bounded canonical findings and returns confirmed/rejected/uncertain rationale and evidence. Wave retains all judgments for human review and includes them in editable review drafts; the judge never auto-posts or silently suppresses a finding.
**Where in Recoder:** `backend/src/domains/agent-os/services/pr-review-agent.service.ts`, `backend/src/domains/agent-os/services/pr-review-findings.service.ts`, and the Wave PR-review surface.

### [SHIPPED] Repo-local review rules, followed by deterministic Checks rows and autofix
**Shipped for installed-app PR reviews 2026-08-30:** repositories can commit bounded required/advisory review rules as versioned JSON or Markdown. The independent validator assesses every rule as pass/fail/unknown with evidence; Wave shows the result and includes it in the editable review draft. Recoder treats repository content as scrutiny criteria, not as permission or a governance override. Separately, `.recoder/checks.json` commands execute as truthful named Checks rows and failures enter readiness.
**Shipped next:** deterministic check rows now distinguish explicit agent-remediation capability from human advisories. JSON review rules can bind an exact named check; its head-pinned result overrides model judgment, persists with the validator workspace, and drives an evidence-based human review suggestion. A failing opted-in rule can launch the governed validator Session continuation directly from Wave, and Recoder—not the fixer—independently attests and refreshes the rule afterward.
**Shipped 2026-08-31:** Wave owns an audited durable Off/Warn/Block policy per repository. When enabled, fresh exact checks linked to required rules enter convergence trust; block mode caps trust low, while actual delivery enforcement remains the independent deployment trust-gate posture. The mode and results are sealed in convergence-evidence v4.
**Where in Recoder:** the rule loader lives in `backend/src/domains/engines/github/github-module.ts`; validator transport and rendering live in agent-os and the Wave PR-review surface. Deterministic execution belongs in conductor readiness and Checks services.

### [SHIPPED] Diff-vs-issue intent/compliance rating wired into canonical requirement ports
**Shipped for installed-app PR reviews 2026-08-30:** the independent validator rates the bounded diff against the PR description and referenced requirements as aligned/partial/misaligned/unknown, records unmet and out-of-scope items, and exposes them in Wave and human review drafts even when defect findings are empty. Same-repository GitHub issue requirements are resolved canonically and bounded through local `gh`, with closed and inaccessible state represented truthfully.
**Shipped 2026-08-31:** explicit Jira keys and browse URLs resolve read-only through Jira Cloud REST v3 alongside GitHub and Beads. Missing configuration, inaccessible records, and transport faults remain unknown. Required check-backed repository rules have a separate operator-owned convergence-trust policy; ticket state alone is never treated as fulfillment.
**Where in Recoder:** GitHub resolution lives in `GithubModule.reviewPR`; Beads and Jira resolution are late-bound canonical ports in agent-os; all three feed the validator contract and Wave review surface.

### [SHIPPED] Accept/reject feedback flywheel: capture trust-flag decisions that calibrate future trust
**Why:** Cursor (learned rules), Greptile, Ellipsis, and Graphite all turn human accept/dismiss into durable per-repo suppression and a published FP rate — this is how they keep signal high. Recoder already has the Checks/merge-outcome view AND a memory-candidate lifecycle, so it can close this loop natively: instrument whether the developer accepted the converged merge / each contested-file pick / each trust flag, emit evidence-backed memory candidates, and use embedding retrieval over past decisions to suppress low-value flags. Also start tracking Recoder's own FP rate as a truthful-health metric.
**Where in Recoder:** `recoder-compare.tsx / MergeVerdictLine telemetry -> recoder_remember memory candidates; consumed by convergence-trust.ts`

**Shipped 2026-08-30:** the repository PR-review rule profile and longitudinal feedback history are visible in Wave. Durable counters survive restart, rule replacement, and Clear; legacy active rules migrate with explicit coverage. Every successful composed delivery separately writes a bounded repository-scoped record of contested picks and trust flags the operator proceeded with. Wave then exposes explicit Accept risk / Dismiss noise / Restore controls for those recorded flags. Only those governed human dispositions calibrate future trust: accepted exact matches remain visible with a bounded confirmed-risk deduction; dismissed exact matches stop repeating without restoring any evidence penalty. Active rules and append-only decision history share the installed app's canonical KV and survive restart. A successful merge alone remains “proceeded with,” never a false-positive dismissal.

### [PARTIALLY SHIPPED] Add a deterministic security layer to the gate: secret-scan + SAST + changed-dependency risk on the diff
**Shipped:** the pure diff scanner redacts and hard-blocks high-signal added credentials, hard-blocks added package lifecycle hooks, and emits review advisories for new/non-registry dependencies and lockfile additions over 500 lines. Readiness owns the verdict and Wave shows both hard blockers and softer review evidence.
**Remaining:** run full SAST (for example Semgrep/ast-grep) in the future sandbox, detect native binaries, consult vulnerability and license data for changed dependencies, and optionally project analyzer results as individually named Checks rows.
**Where in Recoder:** `backend/src/domains/conductor/services/security-scan.service.ts`, `services/readiness.service.ts`, and the Wave Review readiness evidence surface.

### [SHIPPED] Three-way merge verdict: explicit human escalation in the trust gate
**Shipped 2026-08-30:** an unjudgeable merge is distinct from a judged bad merge. In block posture, Recoder refuses before mutation with an `escalated` decision; the HTTP edge preserves it as a structured conflict outcome, and Wave renders **Human review required**. A judged low-trust refusal renders separately as **Blocked by convergence trust**. Warn posture retains escalation as visible advice without silently changing operator policy.
**Where in Recoder:** `backend/src/domains/conductor/evidence/merge-trust-gate.ts`, `module/governed-writes.ts`, `routes/conductor.routes.ts`, and both Wave merge surfaces.

### [SHIPPED] Keep cross-file impact available without the donor graph
**Shipped:** the installed review path projects RecoderGit upstream and downstream reach, graph risk, tests, process membership, depth, co-change history, and cross-repository consumers into Wave and every PR agent prompt. The packaged graph confirms definition-backed calls across four language families, maps exact entrypoints to their dependency paths, reports repeated historical file pairs, and identifies exact consumer files across indexed npm, Python, Go, and Cargo repositories. It caps changed symbols, query pages, files, process paths, commits, history neighbors, and consumer rows. Partial and unavailable results carry their cause.
**Remaining:** exercise the installed registry against representative multi-repository product graphs and add package metadata forms that those repositories expose.
**Where in Recoder:** `backend/src/domains/engines/github/github-module.ts`, `backend/src/domains/engines/recodergit-service.ts`, the agent-os PR review port and service, and the Wave PR-review surface.

### [PARTIALLY SHIPPED] Write review findings back to GitHub
**Shipped:** Wave can publish human-owned native Comment / Approve / Request changes reviews and selected head-bound inline findings. The watcher opens a fresh canonical cohort for every new head SHA, and stable hidden finding keys synchronize open/resolved/outdated GitHub thread state back into Wave.
**Remaining:** publish an advisory three-state Recoder status check that teams may optionally promote through branch protection. This is a host integration, not a prerequisite for the installed-app product loop.
**Where in Recoder:** the existing GitHub review adapter and PR watcher state; a future status adapter beside them.

### [M] Semantic AST diff + copy/move detection for the compare view and contested-file picker
**Why:** Baz (Difftastic) and Devin (move/copy detection) cut diff noise and correctly handle relocated code — precisely the weak spot of Recoder's N-up contested-file picker when parallel agents relocate or rename code and it shows as delete+insert. A tree-sitter/Difftastic semantic diff lets the picker reason at node level and lets convergence conflicts be semantic, not whitespace (also helps: format-on-write before converge, per opencode).
**Where in Recoder:** `backend/src/domains/conductor/services/compare.service.ts / pairwise-diff.service.ts + recoder-compare.tsx / recoder-compare-heatmap.ts`

### [M] Publish measured review precision before changing the trust gate default
**Why:** The gate defaults to `warn`, so Recoder advises on a low-trust merge unless an operator selects `block`. Graphite treats precision as a product asset and publishes a sub-3% false-positive claim. Recoder should measure validator outcomes and operator Accept/Dismiss decisions before offering a block-by-default profile.
**Where in Recoder:** `merge-trust-gate.ts` plus an autonomy/false-positive report in the desktop Checks surface.

## Recoder today (capability map)

**Capabilities:**
- MERGE-READINESS FOLD (6 signals): backend/src/domains/conductor/services/readiness.service.ts `foldReadiness()` is a PURE fold of six merge-decision signals (lifecycle, worktree, merge, checks, preview, openWork) into one truthful ReadinessView with verdict ready|blocked|not_ready|unknown|delivered|terminal, hard `blockers[]`, soft `advisories[]`, PR identity, and an advisory `review` passthrough. Degrade-truthful: an unjudgeable signal is 'unknown', never a fabricated pass.
- GIT TRIAL-MERGE PREFLIGHT: backend/src/domains/conductor/services/mergeability.service.ts runs side-effect-free `git merge-tree --write-tree --name-only <base> <branch>` (clean vs conflicting + conflicted paths) plus `git rev-list --left-right --count` for ahead/behind divergence. Handles too-old-git, no-worktree, no-git degrades to available:false/verdict:'unknown'.
- WORKTREE UNCOMMITTED-STATE PROBE: backend/src/domains/conductor/services/worktree-status.service.ts runs `git status --porcelain`, counts changed paths, surfaces uncommitted work that the committed-state merge would silently drop (soft readiness downgrade).
- PR STATUS + CHECK ROLLUP: backend/src/domains/conductor/services/pr-status.service.ts runs `gh pr view <branch> --json number,state,isDraft,mergeable,url,statusCheckRollup`, `summarizeChecks()` folds GitHub CheckRun/StatusContext entries into worst-wins passing|failing|pending|none counts. This is the ONLY 'CI checks' input and it only mirrors GitHub's existing checks — Recoder runs no checks of its own.
- OPEN-WORK SIGNAL: backend/src/domains/conductor/services/openwork.service.ts `foldOpenWork()` folds three sources — unchecked `- [ ]` acceptance criteria in the task-spec body (`parseUncheckedCriteria`), added TODO/FIXME/XXX/HACK markers in the merge diff (`parseDiffTodos`, regex over added `+` lines), and non-closed linked bd issues — into capped advisory items.
- CONVERGENCE TRUST SCORE: backend/src/domains/conductor/evidence/convergence-trust.ts `computeConvergenceTrust()` is a pure deterministic 0-100 score + tier (high>=75 / medium>=45 / low) + weighted explainable factors + reviewFlags, over verification verdict/blockers (crux, blocked caps at 30), convergence provenance (clean-merge ratio, LLM-assisted regions, contested picks), governance (degraded path / risk tier / approval), and breadth (>=2 candidates).
- MERGE TRUST GATE (enforced): backend/src/domains/conductor/evidence/merge-trust-gate.ts `evaluateMergeTrustGate()` (off/warn/block via RECODER_MERGE_TRUST_GATE, default warn) is applied at merge time in backend/src/domains/conductor/module/governed-writes.ts (~L1152-1195) — block mode REFUSES a low-trust merge before mutation; warn attaches an advisory; result carries trustTier/trustScore/trustWarning/trustFlags.
- ADVISORY AI PR AUTO-REVIEW: Conductor readiness and the installed agent-os watcher consume one shared normalized ledger from `GithubModule.reviewPR`: bounded upstream and downstream files, affected tests, process paths, depth, risk, scope, and partial state. Review renders the same evidence as Wave. Both paths remain advisory and do not change the readiness verdict.
- CODE-KNOWLEDGE-GRAPH INDEXING + CODE-INTEL QUERIES: backend/src/domains/engines/recodergit-service.ts owns the recodergit engine indexing lifecycle (in-process `runFullAnalysis` first, CLI-spawn fallback), tracks truthful per-repo index status indexed|stale|not_indexed|unavailable (sha-based staleness), projects a DomainMap (route/group map), and exposes CodeIntelOps symbol_search (query), find_references (impact upstream), call_graph (impact downstream), definition (360 context). Default-ON (RECODER_CODE_GRAPH_ENABLED), fail-safe, supervises a loopback `recodergit mcp --http` server with a real readiness probe.
- PERMISSIVE PACKAGED CODE INTELLIGENCE: `permissive-code-search.ts` composes MIT semantic search over shared embedding/vector ports and a short-lived MIT static import graph. Packaged `find_references` and `call_graph` return file-level reach for changed TypeScript/JavaScript files. `definition` still requires the donor symbol graph.
- CONVERGENCE EVIDENCE (sealed, exportable): backend/src/domains/conductor/evidence/convergence-evidence.ts assembles a content-hashed (SHA-256) record of task + N candidate diffs (by hash) + chosen candidate + governance verdict/approval + pre-merge verification + per-file selections (pick|synthesize provenance), sealed into a Merkle audit chain (auditEntryHash) — the auditable 'what converged under what authority' artifact.
- READINESS COMPOSITION: backend/src/domains/conductor/module/reads.ts fires all probes via Promise.allSettled (each degrades independently), then calls foldReadiness; probePrReview attaches the advisory review; gathers open-work raw material (task body, merge diff, linked issues) for foldOpenWork.
- CODEMAP LAUNCH FUSION: the conductor enriches an agent's launch prompt with a recodergit code-knowledge-graph context block (codeIntel.queryContext with deterministic repoId + prompt-derived seed terms), appended after the memory-recall block (backend/src/domains/conductor/conductor-launch-codemap.test.ts documents the wiring; adapters/code-intel.adapter.ts `deriveSeedTerms`).
- COLBERT RERANK SIDECAR: backend/src/domains/engines/colbert-daemon.ts supervises `rerank_server.py` as a loopback sidecar for recall ranking (memory domain, not merge-gating); degrade-truthful to identity/lexical order when torch/sidecar absent.
- DESKTOP CHECKS SURFACE: apps/desktop/app/frontend/app/view/recoder/recoder-checks-summary.ts (`summarizeChecks` rollup ready|blocked|discouraged|quiet + `buildChecksTable`) and recoder-compare.tsx render ChecksPanel (one merge-readiness row per sibling with itemized blockers/advisories), ReadinessBadge (6 signals + PR link), MergeabilityBadge (conflict paths), and MergeVerdictLine (trust tier/score/warning + reviewFlags checklist).

**Signals computed:**
- Six readiness signals, fixed order, each pass|fail|pending|unknown: lifecycle, worktree, merge, checks, preview, openWork (readiness.service.ts).
- Overall merge verdict: ready | blocked | not_ready | unknown | delivered | terminal, with hard `blockers[]` (conflict paths / failing-check count) and soft `advisories[]` (unchecked criteria, added TODOs, open linked issues).
- Mergeability verdict: clean | conflicting | unknown, plus conflicted path list and ahead/behind divergence counts vs the resolved base branch (mergeability.service.ts).
- Worktree dirty flag + changedCount from `git status --porcelain` (worktree-status.service.ts).
- PR check rollup: passing | failing | pending | none with total/passed/failed/pending counts, plus PR number/state/draft/mergeable/url (pr-status.service.ts).
- Open-work items by kind: criterion (unchecked task-spec boxes) / todo (added diff markers) / issue (non-closed bd issues), capped at 50 (openwork.service.ts).
- Convergence trust: 0-100 score + tier high/medium/low + signed weighted factors (verification, clean-merge-ratio, llm-assisted-merge, contested-picks, governance, risk-tier, approval, breadth) + reviewFlags[] + one-line summary (convergence-trust.ts).
- Merge trust gate decision: allow / blocked / warning + tier + score, echoed onto the merge result as trustTier/trustScore/trustWarning/trustFlags (merge-trust-gate.ts, governed-writes.ts).
- Blast-radius impact: the installed review loop and Conductor readiness carry one bounded RecoderGit file/test/process/history/consumer ledger with both directions, changed-together pairs, cross-repository files, depth, risk, scope, and partial state.
- Code-graph index stats: nodes / edges / clusters / flows and index freshness indexed|stale|not_indexed|unavailable via HEAD-sha comparison (recodergit-service.ts).
- Preview verification passthrough: passed | failed | skipped | degraded (from preview-verify.port; degraded proves nothing → 'unknown').
- Desktop Checks rollup tone per sibling: ready | blocked | discouraged | quiet with hardCount blockers / softCount advisories (recoder-checks-summary.ts).

**Honest gaps:**
- The separate judge is an advisory agent execution with explicit evidence and visible coverage, but Recoder does not yet measure aggregate false-positive or resolution rate, and it has no deterministic verification-script artifact attached to every judgment.
- Recoder-owned explicit-argv checks cover local or opt-in off-box execution, and repository-configured stdio LSP servers produce base-versus-head deltas. The remaining analysis gap is automatic coverage/SAST/dependency policy beyond repository declarations.
- The deterministic security slice covers added secrets, package lifecycle hooks, new/non-registry dependencies, and oversized lockfile churn. It still lacks full SAST, native-binary detection, and vulnerable-dependency/license lookup.
- The shipped DMG excludes the rich PolyForm symbol graph. Its MIT fallback covers TypeScript/JavaScript aliases, configured Python roots, Go module/workspace replacements, Rust modules/local crates including `#[path]` at file scope, static symbol calls, process membership, and co-change history. Definition lookup and dynamic/runtime import behavior need broader permissive analysis.
- RecoderGit's canonical index state and compact MIT dependency graph snapshot persist through installed-app KV. The snapshot requires an exact repository root and source revision; tracked diff or untracked file changes force a rebuild.
- Trust gate default does not block: RECODER_MERGE_TRUST_GATE defaults to 'warn' (merge-trust-gate.ts), so out of the box a low-trust converged merge is only advised, never refused, unless an operator explicitly sets 'block'.
- Open-work / TODO detection is naive regex on added diff lines only (parseDiffTodos) and checkbox parsing of the task body — no semantic detection of unfinished work, stubbed functions, `throw new Error('not implemented')`, or dead code.
- Repository-owned conventions can now receive advisory pass/fail/unknown judgments with evidence. Recoder still lacks deterministic architectural and cross-file lint, diff-size and risk heuristics beyond blast radius, and PR-description or commit-message quality checks.
- ColBERT rerank is typically a no-op in practice (torch usually absent per docs/RECODER-ARCHITECTURE.md L124), so retrieval ranking quality that could feed review context degrades to lexical/identity order.
- The standing local watcher re-reviews each head SHA and tracks native thread resolution, but it does not publish a native advisory GitHub status check that teams can promote through branch protection.

### Cursor Bugbot (+ Background Agents / Cloud Agents)
*AI-PR-review-bot + background-agent (closed-source)* — closed-source

**Ingestion:** Closed-source, but Cursor's own engineering blog ("Building a better Bugbot") and docs describe it concretely. Bugbot is an AGENTIC reviewer, NOT a whole-repo static index. It starts from the PR DIFF and pulls cross-file context DYNAMICALLY at runtime via tool calls ("The agent could reason over the diff, call tools, and decide where to dig deeper"). Repo access is a custom Git integration "rebuilt in Rust" that minimizes data fetched, with rate-limit monitoring, request batching, and proxy infrastructure to stay within GitHub API constraints (i.e. they treat GitHub as a metered, rate-limited data source, not a full clone-and-index). Key insight: they moved information OUT of static upfront context INTO dynamic context — "the model consistently pulled in the additional context it needed at runtime, without requiring everything to be provided ahead of time." Bugbot also ingests existing PR discussion (top-level + inline comments) as context to avoid duplicate findings and build on prior feedback. Rules/context are layered from .cursor/BUGBOT.md files: it always loads the root file then traverses UPWARD from each changed file's path to find directory-scoped rule files (path-relevant context loading). Background/Cloud Agents (the fix + long-task side) instead do a FULL clone into a per-task isolated VM with a complete dev environment (deps, secrets, network); each task gets its own VM with no shared state, works on its own branch, runs builds/tests, and as of Feb 2026 has "Computer Use" (a real desktop + browser) to visually verify changes.

**Checks run:**
- Semantic logic bugs, NOT lint/style: deliberately narrow scope — null-pointer/deref, race conditions, missing error handling, edge cases, incorrect error handling, security vulns, performance. Explicitly ignores formatting/style/low-severity (that's what makes signal high).
- Cross-file interaction bug: reasons about how the changed code interacts with existing components and assumptions made ELSEWHERE (e.g. 'other endpoints handle this error, this one doesn't') — the class human reviewers miss.
- Severity classification: every finding tagged high/medium/low.
- Category filtering: an explicit filter pass drops unwanted categories (compiler warnings, doc-only errors) before posting.
- False-positive validator pass: results are run through a dedicated validator MODEL whose job is to catch/suppress false positives before anything is posted.
- Dedup across runs: findings are deduped against bugs posted from previous runs on the same PR, and auto-closed if a matching prior finding was resolved.
- Resolution-rate signal (their north-star metric): an LLM judges at merge time whether each flagged bug was ACTUALLY resolved by the author in the final merged code — the review is optimized for bugs-that-get-fixed, not bugs-flagged.
- Learned per-repo rules: dismiss/critical feedback trains suppression or higher-confidence surfacing per codebase (reportedly 44k+ learned rules across 110k+ repos).
- Team/repo/project custom rules enforced (Result-pattern, conventions) merged in precedence order Team -> project files -> learned -> manual.

**Merge gate:** Bugbot posts a GitHub App status check named "Cursor Bugbot" with three conclusions: success (no issues, no unresolved prior comments), neutral (issues found OR review cancelled — the DEFAULT when findings exist), and failure (issues found AND 'fail-on-unresolved' is explicitly configured). Crucially: findings default to `neutral`, so even if you make the check a required branch-protection rule, "requiring the status alone does not block merges on findings because findings default to neutral" — teams must opt into fail-on-unresolved to make it a hard gate. So the default posture is ADVISORY (inline comments + suggested fixes), not blocking. Remediation is offered via 'Fix in Cursor' / 'Fix in Web' links and Bugbot Autofix (Beta), which spawns a Cloud Agent in an isolated VM to fix the bug and push a commit to the PR branch (or a new branch), capped at max 3 attempts to prevent loops. Cloud/Background Agents produce the evidence side of the gate: they attach videos, screenshots, and logs to the PR so reviewers validate without checking out the branch. Trigger model: auto on every PR update by default, or manual via `bugbot run` / `cursor review` comment (add verbose=true to see loaded rules + request IDs); configurable to run-only-when-mentioned or run-once. Effort levels (Default/High/Custom) trade analysis depth vs cost. Reported: 70%+ resolution rate, ~2M PRs/month.

**Lessons for Recoder:**
- Add a false-positive VALIDATOR stage to the convergence-trust / Checks surface: run every candidate review finding (from any parallel agent) through a separate model whose only job is to confirm or suppress it before it reaches the merge decision. This is a distinct, testable pipeline stage Recoder can own.
- Adopt 'resolution rate' as a first-class merge-readiness signal: judge (LLM) whether each flagged concern was actually addressed in the converged diff at merge time, and optimize the whole Checks surface for fixed-not-flagged. This aligns perfectly with Recoder's evidence-backed merge thesis and gives a truthful, measurable trust number.
- Prefer diff-first dynamic context over building/maintaining a heavy repo index for the review pass: let the reviewing agent pull cross-file context via tools (recoder_repo_search / recoder_repo_diff already exist). Reserve full clone/index for the fix/verify substrate — mirrors Cursor's cheap-reviewer vs full-VM-fixer split, which Recoder already has (worktrees vs review).
- Make the merge gate ADVISORY-by-default with opt-in hard-block, exposed as a GitHub-style status check with success/neutral/failure conclusions. Recoder's convergence-trust warn-vs-block default already matches this — codify the three-state status check and the 'requiring the check alone does not block on neutral findings' nuance so teams choose the strictness.
- Cross-file interaction analysis is the highest-value check: explicitly compute 'does this change violate an assumption made elsewhere' (e.g. sibling handlers/endpoints) rather than diff-local lint. This is exactly the bug class parallel-agent convergence should catch and is a concrete signal to add to the Checks surface.
- Path-scoped, upward-traversing rules file (Recoder equivalent of .cursor/BUGBOT.md): load root policy then merge directory-scoped rules for each changed path, with an explicit precedence order (team -> project -> learned -> manual) and character caps. Cleaner than one global prompt.
- Capture accept/dismiss feedback into LEARNED per-repo suppression/priority rules — turns human review of Recoder findings into durable, evidence-backed memory candidates (fits Recoder's memory-candidate model exactly).
- Autofix loop cap: when auto-remediating a finding, cap attempts (Cursor uses 3) and push to a branch to prevent infinite fix loops — a cheap safety guardrail for Recoder's converge/autofix path.
- Attach verification artifacts (screenshots/logs/video, browser 'computer use') directly to the merge surface so reviewers validate without checkout — reinforces Recoder's 'never imply success without evidence' rule; Recoder's browser_verify + attach_artifact tools already enable this.
- Category-filter stage: explicitly drop low-value categories (compiler warnings, doc-only nits) before surfacing, so the Checks surface stays high-signal and the trust score isn't diluted by noise.

### CodeRabbit
*AI-PR-review-bot* — closed-source

**Ingestion:** Per-PR ephemeral sandbox, NOT a persistent pre-built index. On each PR, a job service clones the FULL repo into an isolated, disposable microVM (GCP Cloud Run Sandboxes; ~1hr timeout, 8 vCPU, 32 GiB RAM, repo held in memory). Untrusted contributor code is double-isolated: microVM + Jailkit-confined processes. Three ingestion layers run per review: (1) CODE GRAPH ("Codegraph") built FRESH every review — a lightweight structural map of definitions/references plus a scan of commit history for files that frequently change together; rebuilt each time deliberately so no new cross-file dependency is missed (call sites in other files are visited even when they share no keywords with the diff). Results render in the PR Walkthrough as two tables (failed checks surfaced prominently). Recommended rollout is warning-first, promote to error only once a check proves high-signal. (2) The actual BLOCK comes from pairing error-mode checks with the 'Request Changes Workflow': CodeRabbit posts a GitHub 'Request Changes' PR review that keeps the PR unmerged until the issue is fixed OR an authorized user explicitly overrides — combined with GitHub branch protection this becomes a hard merge gate. Net model: deterministic AI-enforced checklist + human-overridable request-changes review, rather than a purely mechanical pass/fail status.

- Add a deterministic static layer UNDER the model: run the repo's own linters + Semgrep/Gitleaks/ast-grep inside the sandbox and fold their findings into the merge Checks surface, so the trust score isn't purely model-derived.
- Adopt an explicit two-mode gate (warning -> error) with human override, mirroring CodeRabbit's Request-Changes workflow — this is a concrete, shippable design for our merge trust gate's warn/block modes and the override audit trail.
- Add intent-alignment as a first-class merge check: diff-vs-linked-issue/task-spec scope assessment (flag out-of-scope changes) — a natural fit for Recoder task specs and the open-work signal.
- Use a cheap-model context-compression + judge-model verification pipeline (their 7-8 model ensemble) to control cost while keeping a high-signal final pass — applicable to our convergence trust scoring across N parallel worktree runs.
- Give the reviewing/verifying agent raw sandbox shell + AST tools (ast-grep) and a fixed recursion cap instead of bespoke tool schemas — reduces maintenance and matches our recoder_sandbox_exec substrate.
- Built-in checks worth copying verbatim into our Checks surface: docstring/coverage threshold, PR title/description conformance, linked-issue verification, and mergeability trial-merge — cheap, deterministic, high-signal.
- Note their weakness to exploit: cross-REPO context is where CodeRabbit 'loses the plot' (shared libs/microservices in other repos flagged as broken). Recoder's parallel-worktree + retrieval/ingest layer could ingest sibling repos/packages to give multi-repo blast-radius as a differentiator.

### Greptile

### Qodo Merge / PR-Agent (Qodo, formerly Codium AI)
*AI-PR-review-bot* — OSS: https://github.com/qodo-ai/pr-agent

**Ingestion:** Diff-centric, NOT repo-index-centric. There is no clone, tree-sitter AST, embeddings, call graph, or LSP in the OSS core — it operates on the PR patch pulled via git-provider REST APIs (`git_providers/github_provider.py` etc., `get_diff_files()`). The engine is an "adaptive, token-aware patch fitting" compressor (`pr_agent/algo/pr_processing.py`): (1) `sort_files_by_main_languages()` groups/prioritizes files by the repo's dominant languages (via `language_extensions.toml`); (2) `pr_generate_extended_diff()` calls `extend_patch()` to add surrounding context lines, `PATCH_EXTRA_LINES_BEFORE/AFTER` capped at `MAX_EXTRA_LINES=10`; (3) token budgeting through `token_handler.count_tokens()` / `get_max_tokens()` with `OUTPUT_BUFFER_TOKENS_SOFT_THRESHOLD=1500` (triggers compression) and `HARD_THRESHOLD=1000`; (4) when over budget `pr_generate_compressed_diff()` sorts files by token count desc, drops deletion-only hunks via `handle_patch_deletions()`, renumbers with `decouple_and_convert_to_hunks_with_lines_numbers()`, and `clip_tokens()` truncates the added/modified/deleted file lists; (5) `get_pr_multi_diffs()` splits huge PRs across multiple LLM calls. ### Sweep (sweepai/sweep)
*AI-PR-review-bot + issue-to-PR agent (original OSS repo; product later pivoted to a JetBrains IDE plugin)* — OSS: https://github.com/sweepai/sweep

**Ingestion:** Full git clone of the repo (ClonedRepo), then a HYBRID retrieval index built per run, not a persistent semantic graph:
1. CHUNKING via tree-sitter — sweepai/utils/code_validators.py `chunk_code`/`get_parser` uses `tree_sitter` + `tree_sitter_languages` (python/js/ts/etc.), falling back to naive line chunking on parse failure. sweepai/core/repo_parsing_utils.py `directory_to_chunks` filters files first (skips >240KB, <10B, binary/NUL, avg line >200 chars, low token-density non-human-readable, excluded dirs/exts).
2. LEXICAL index — sweepai/core/lexical_search.py builds a Tantivy (Rust BM25) index (`CustomIndex`, schema title/body/doc_id) with a custom code tokenizer that splits camelCase/snake_case and drops low-signal tokens; results limit 200. Cached in diskcache + Redis.
3. VECTOR index — sweepai/core/vector_db.py `embed_text_array` embeds chunks with OpenAI `text-embedding-3-small` OR Voyage `voyage-code-2` (`multi_get_query_texts_similarity`, cosine_similarity).
4. RERANK — sweepai/utils/ticket_utils.py `get_pointwise_reranked_snippet_scores`: freezes top-1..5, reranks ranks 6..100 with Cohere/Voyage listwise reranker (scaled scoring). Also sweepai/utils/openai_listwise_reranker.py.
5. DEPENDENCY/IMPORT GRAPH — `build_import_trees` builds a networkx `nx.DiGraph` import graph to pull in related files (get_relevant_context in ticket_utils). Docs describe 'dependency graph + text + vector search'.
6. QUERY EXPANSION — `generate_multi_queries` runs multi-query fan-out then fuses lexical+vector scores. The index is rebuilt/cached per ticket (not a long-lived server-side semantic DB).

**Checks run:**
- Diff extraction: repo.compare(base_sha, head_sha), split each file diff into hunks/patches via regex @@ markers (sweepai/core/review_utils.py split_diff_into_patches)
- File filtering: drops sweep_config-excluded files (e.g. package-lock.json) and auto-generated/vendored files via GitHub Linguist (`is_file_bad`), plus undecodable/oversized files -> reported as dropped/unsuitable, not reviewed
- Diff annotation: a Claude-Sonnet 'AnnotateDiffBot' (review_annotations.py) writes an objective, speculation-free functional explanation of each hunk against post-change source, fed into the reviewer as context
- Related-file grouping: DBSCAN(eps=0.6, min_samples=2) clusters files by embedding of their patch text so related changes are reviewed together (cluster_patches)
- Group-vote review: 5 independent LLM review passes (multiprocessing, seeds 0-4) per file/group (group_vote_review_pr, GROUP_SIZE=5)
- Functional bug / edge-case check (review_prompts.user_prompt): line-by-line purpose, correctness, accidental/commented-out code, edge cases, alignment with PR intent; explicitly instructed to only surface high-confidence merge-blocking functional issues and ignore string/comment/config/resource noise
- Special/custom rules check: validates diff against user-defined rules in sweep.yaml (system_prompt_special_rules); DEFAULT_RULES = unit tests for new logic, refactor large functions, add docstrings
- Edge-case Q&A pass: generates targeted questions about the diff then answers them to surface hidden production issues (system_prompt_edge_case_question_creation / _answer)
- Duplicate-utility detection: identifies newly-added functions then checks (against retrieved related snippets) whether each duplicates an existing util (system_prompt_identify_new_functions + system_prompt_identify_repeats)
- Issue severity sorting (system_prompt_sort_issues) before rendering
- Generated-code validators (code_validators.get_check_results): tree-sitter syntax check, ruff+pylint for Python, tsc --noEmit + eslint for TS/JS, and NEW-vs-OLD lint diffing so only newly-introduced lint errors are flagged
- Validation loop (docs): runs the repo's unit tests and autoformatters on Sweep-generated code before finalizing a PR
- Existing PR review threads ingested (get_all_comments_for_review via GitHub GraphQL) incl. resolved/outdated state, so the bot accounts for prior human review context

**Merge gate:** ADVISORY, not a hard gate. review_pr (sweepai/handlers/review_pr.py) posts/updates a single PR review comment (create_update_review_pr_comment) listing per-file issues + potential issues + a generated PR summary, and adds an 'eyes' reaction while working. It does NOT auto-merge or set a required status check; humans approve/merge under normal GitHub branch protections and collaborator permissions. Refuses forked-repo PRs. The self-consistency VOTE is the real quality gate: each of the 5 review passes emits issues, every issue is embedded and clustered across passes with DBSCAN(eps=0.375, min_samples=2); an issue cluster is promoted to a REAL issue only if it appears in >=4 of 5 passes (LABEL_THRESHOLD=4), demoted to 'potential issue' at exactly 3, and dropped below that. A representative issue per cluster is chosen (get_group_voted_best_issue_index). This majority-vote across independent samples is explicitly designed to suppress hallucinated/noisy findings. The bot also auto-responds to PR review comments/replies rather than gating merge.

**Lessons for Recoder:**

Concrete, testable hallucination filter that maps onto Recoder's multi-run convergence — Recoder already HAS N parallel worktree runs, so it can vote across the actual agents instead of re-sampling one reviewer (review_utils.group_vote_review_pr, LABEL_THRESHOLD=4)

### Aider (Aider-AI/aider)
*Terminal AI pair-programming agent (git-native, auto-commit); not a PR-review/merge-gate bot* — OSS: https://github.com/Aider-AI/aider

**Ingestion:** Git-native, whole-repo static index — no embeddings, no LSP, no cloud service. (1) Enumerates git-tracked files via GitPython (repo.py get_tracked_files: walks HEAD tree + staged index, applies .aiderignore/subtree filters). (2) REPO MAP (repomap.py): parses each source file with tree-sitter and runs per-language tag queries (aider/queries/tree-sitter-language-pack/<lang>-tags.scm) to extract "tags" = symbol definitions (name.definition.*) and references (name.reference.*). Tags are cached in a per-repo SQLite disk cache (.aider.tags.cache.v4 via diskcache) keyed by file mtime, so re-indexing is incremental. For languages whose query only emits defs (e.g. C++), it backfills references with a pygments lexer pass. (3) Builds a dependency graph as a networkx MultiDiGraph: nodes = files, edges = (referencing file -> defining file) for every shared identifier, edge weight from identifier-importance heuristics. (4) Runs PERSONALIZED PageRank (nx.pagerank) over that graph, with the personalization vector seeded on the files currently in the chat plus any files/identifiers the user mentioned. It then distributes each node's rank across its out-edges to rank individual symbol *definitions*, not just files. Identifier weight heuristics: mentioned idents x10; long snake/kebab/camelCase idents (>=8 chars) x10; private _-prefixed idents x0.1; idents defined in >5 files x0.1; references coming from in-chat files x50; sqrt(num_refs) damping so high-frequency names don't dominate. (5) Fits the resulting ranked map into a token budget (default --map-tokens 1024, multiplied x8 when no files are in the chat) via a binary search over how many ranked tags to include, rendering surviving definition lines with grep_ast TreeContext.", "

**Checks run:**
- Tree-sitter syntax check (linter.basic_lint): parses edited file, traverses AST for ERROR / is_missing nodes = syntax errors, reports with line context (skips typescript)
- Python compile check (lint_python_compile): py_compile of the edited file, surfaces the traceback + offending line range
- flake8 FATAL-ONLY gate (py_lint.flake8_lint): runs flake8 --isolated --show-source --select=E9,F821,F823,F831,F406,F407,F701,F702,F704,F706 (syntax errors + undefined/undefined-in-__all__ names) — deliberately ignores style noise
- Generic linter: any user --lint-cmd per language; non-zero exit code = failure; parses filename:linenum out of stdout and marks offending lines with a block char via TreeContext
- Auto-test: --test-cmd + --auto-test runs an arbitrary user test/CI command after each edit; non-zero exit = failure (also /test on demand)
- Edit-format validation: search/replace (or diff) blocks are validated against file contents (apply_edits_dry_run) before applying; a non-matching block raises a SearchReplaceNoExactMatch reflection error
- No semantic-diff, no security scan, no mergeability/conflict trial-merge, no review heuristics — those are out of scope for Aider

**Merge gate:** No PR/branch merge gate — Aider edits the working tree directly and is not a merge-gating product. Its verification model is a bounded REFLECTION LOOP inside base_coder.py: after the LLM applies edits, if auto_lint (default ON) it lints the edited files, auto-commits ('Ran the linter'), records lint_outcome, and if there are lint errors it asks the user to confirm, then feeds the lint output back to the model as reflected_message for another pass; auto_test (default OFF) works the same with test output. The loop is capped at max_reflections = 3. Every AI edit is captured as its own git commit with an LLM-generated commit message and (aider) author/committer attribution (or a Co-authored-by trailer); user's pre-existing dirty changes are snapshotted in a separate 'dirty commit' first. This granular auto-commit history is the real 'gate/undo' surface (/undo = git revert). --git-commit-verify controls whether the repo's own pre-commit hooks run on those commits. lint_outcome/test_outcome are tracked but are advisory, not a hard block.

**Lessons for Recoder:**
- Adopt a PageRank-over-tree-sitter-tags repo map as a cheap, language-agnostic 'blast radius / what-to-review' signal: personalize the PageRank vector on the files a worktree actually changed, then rank which OTHER files/symbols a reviewer or the convergence layer must inspect — directly feeds Recoder's Checks surface and 'what to review'
- Run fast deterministic pre-merge checks BEFORE expensive test/trial-merge: tree-sitter ERROR/missing-node syntax scan + a compile check (py_compile-style) catch broken agent edits in milliseconds — a good first readiness gate in convergence
- Copy the bounded reflection loop (lint/test error -> feed output back to the agent -> retry, capped at 3) as the auto-repair step when a candidate branch fails a readiness check, instead of just failing the merge
- Use a curated FATAL-ONLY lint select set (undefined names, syntax, __all__ errors) as the merge-blocking subset and treat style findings as advisory — reduces false-positive review friction and keeps the convergence-trust score meaningful
- Use an mtime-keyed SQLite tag cache for incremental symbol indexing so the same repo can be re-indexed cheaply across N parallel worktrees
- Token-budget the review context via binary search over ranked tags (Aider fits the map to --map-tokens) so an LLM reviewer/convergence judge always gets a bounded, highest-signal slice of the diff's blast radius
- Emulate per-step auto-commit with generated messages inside each agent worktree: it makes convergence diffs granular, attributable, and revertible, and gives the merge view a clean commit-by-commit story instead of one giant squash
- Note the gap to exploit: Aider has NO mergeability/conflict trial-merge, NO security scan, NO semantic diff — Recoder's trial-merge, convergence-trust score, and evidence-backed Checks tab are exactly the layer Aider omits, so lead with those as differentiation rather than repo-mapping

File discovery via walkDir/DFSWalker respecting .gitignore + .continueignore + DEFAULT_SECURITY_IGNORE_FILETYPES (never indexes .env/*.key), MAX_FILE_SIZE_BYTES=5MB. Incremental sync is merkle-like: getComputeDeleteAddRemove (refreshIndex.ts) diffs the filesystem against SQLite tag_catalog (file hash+timestamp keyed by IndexTag = directory/branch/artifact), so each git branch/worktree is its own index tag; IndexLock serializes, files batched ~200. Retrieval (core/context/retrieval/pipelines/RerankerRetrievalPipeline.ts) FUSES four sources — recently-edited files + FTS chunks + embeddings chunks + repo-map (an LLM picks which files to read from a generated repo map, requestFilesFromRepoMap) — dedupes (deduplicateChunks), optionally expands top hits with more embeddings neighbors, then reranks and slices to nFinal (NoRerankerRetrievalPipeline is the fallback when no reranker configured). NOT a call/dependency graph or LSP-based blast-radius; retrieval is chunk-RAG + repo-map, review is git-diff-scoped.

**Checks run:**
- security-audit (checks/security-audit.md): audits the PR diff for NEW vulnerabilities, specifically prompt-injection sources and local-machine risks; AUTOFIXES ('make the required changes')
- anti-slop (checks/anti-slop.md): detects 10 AI-slop patterns (verbose restating comments, excessive defensive checks, redundant type annotations, boilerplate/over-abstraction, over-long names, single-use intermediate vars, copy-pasted try/catch, filler JSDoc, 'just in case' dead code) and makes targeted cleanups, max one file
- stale-comments (checks/stale-comments.md): flags comments that contradict adjacent code, TODO/FIXME/HACK for work already done, and commented-out code with misleading 'keep this' annotations
- react-best-practices, setup-scripts, update-agents-md, update-continue-docs (checks/*): framework-hygiene + keep AGENTS.md/docs in sync with the diff
- breaking-change-detector (agents/breaking-change-detector.md): scans for renamed/removed CLI commands, public API signature changes, config-schema changes, and hardcoded-URL changes that leave STALE REFERENCES elsewhere (docs, skills, workflows, callers); fixes refs or comments if no migration path
- test-coverage (agents/test-coverage.md): heuristic on whether new exported fns/classes, new CLI commands, bug fixes, or new endpoints need tests (happy/edge/error path, regression test for bug fixes); COMMENTS gaps, explicitly does NOT write tests; exempts docs/config/CSS/dep-bumps/refactors
- dependency-security-review (agents/dependency-security-review.md): reviews package.json changes — new dep maintenance/known-vulns/pinning, major-version breaking usage, removed-dep dangling imports; flags postinstall scripts, native/.node binaries, filesystem/network-access deps, and package-lock.json diffs >500 lines as human-review triggers
- error-message-quality, input-validation (agents/*): advisory quality checks on the diff
- All prompts are diff-scoped by rule: 'Do NOT look into anything unless it was changed in the pull request' / 'Focus only on changes introduced in this PR' to bound blast radius and false positives
- Separate CI workflows add: Snyk vuln auto-fix (snyk-agent.yaml), auto-fix-failed-tests.yml, similar-issues.yml issue-triage, plus standard lint/test pr-checks.yaml + cli-pr-checks.yml

**Merge gate:** Reusable GitHub Actions workflow .github/workflows/continue-agents.yml. A 'discover' job scans .continue/agents (and .continue/checks) for markdown files and emits a matrix; a 'run-agent' job installs the Continue CLI (cn) and runs each definition non-interactively via `cn -p --agent <file>` with an Anthropic key. Each run becomes a first-class GitHub Check Run titled 'Continue: <agent-name>', with conclusion success/failure and the agent output attached (truncated to 60KB). A non-zero agent exit fails that job → the PR status check goes red; making it required branch protection turns it into a hard gate. Two behavioral tiers: 'checks' have contents:write and COMMIT autofixes to the PR; 'agents' are advisory and post pull_request comments (pull-requests:write). This is not a single trust score or trial-merge — it is a fan-out of independent, per-concern check runs, each individually pass/fail with evidence. Product framing = 'Continuous AI': headless CLI for async CI PR review + interactive TUI; BYOK models (Claude/GPT/Gemini/Ollama/LM Studio). Caveat: one secondary source claims a Cursor acquisition made v2.0.0 the final release with the repo read-only in 2026 — UNVERIFIED; the repo and workflows above are still present and active.

**Lessons for Recoder:**
- Make Recoder's Checks surface load repo-local, version-controlled check specs (markdown/YAML in a .recoder/checks dir) and fan them out as a matrix — each producing one truthful pass/fail with evidence — instead of a monolithic reviewer prompt; this is auditable and mirrors Continue's .continue/checks model
- Adopt the autofix-vs-advisory split in the convergence layer: tag each check as auto-remediable (agent commits the fix into the worktree) vs flag-for-human (surfaces in the Checks tab / trust review flags) — Recoder already distinguishes advisory 'warn' vs 'block'; add the remediation dimension
- Steal these concrete, cheap, high-signal checks that don't need heavy infra: anti-slop (10 patterns), stale/misleading-comment detector, breaking-change/stale-reference detector (renamed CLI/API/config/URL leaving dangling refs), dependency postinstall+native-binary+>500-line-lockfile-diff → human-review trigger, and the test-coverage-expected heuristic (which change categories require tests, which are exempt)
- Enforce diff-scoping in every check prompt ('only files changed in this run/PR') to keep the convergence trust score from drowning in pre-existing-issue noise — pairs with Recoder's open-work signal
- Reuse Continue's per-branch IndexTag idea: key the retrieval/index cache by worktree branch so N parallel agent worktrees each get an isolated incremental (merkle tag_catalog) index without cross-contamination
- For 'what to review' context assembly, copy the 4-source retrieval fusion (recently-edited + FTS/BM25 + embeddings + LLM repo-map file-picking) then rerank to nFinal — the repo-map file-picker gives useful context even when embeddings are unavailable, a robust degrade path
- Never index secrets: adopt a DEFAULT_SECURITY_IGNORE_FILETYPES (.env/*.key) + 5MB file cap at the ingestion boundary, consistent with Recoder's no-secrets-in-packages rule

### opencode (sst/opencode)
*Open-source terminal coding agent (substrate, NOT a PR-review/merge-gate tool)* — OSS: https://github.com/sst/opencode

**Ingestion:** No embeddings / vector DB / persistent semantic index and no tree-sitter AST index. opencode reads a repo on-demand through built-in tools: ripgrep-backed `grep` (regex over file contents, `packages/core/src/ripgrep` used by `packages/opencode/src/tool/grep.ts`), `glob`, and a `read` tool with context guards (DEFAULT_READ_LIMIT=2000 lines, MAX_BYTES=50KB, per-line 2000-char truncation, binary-sniff via 4KB sample) in `tool/read.ts`. The real code-intelligence layer is LSP, not an index: `packages/opencode/src/lsp/lsp.ts` starts language servers lazily by file extension (`lsp/language.ts` maps ~90 extensions) and the read tool "warms" the server via `lsp.touchFile`. The LSP service exposes hover, definition, references, implementation, documentSymbol, workspaceSymbol, and prepareCallHierarchy/callHierarchy — i.e. a LIVE (queried, not precomputed) call/reference graph and blast-radius capability, always fresh and language-accurate. A separate shadow-git snapshot store (`snapshot/index.ts`) mirrors the worktree under its own `--git-dir` and uses `objects/info/alternates` pointing at the source repo so it does not re-hash huge checkouts (comment cites chromium-scale repos), giving cheap track/patch/restore/revert/diff/diffFull per session. Real git worktrees are supported (`worktree/index.ts`: create/list/remove/reset with branch + startCommand) for parallel isolated runs.

**Checks run:**
- Post-edit LSP diagnostics loop (the primary automated check): after every edit/write, tool/edit.ts calls lsp.touchFile(file,'document') + lsp.diagnostics(), then LSP.Diagnostic.report() and injects 'LSP errors detected in this file, please fix:\n<diagnostics ...>' back into the tool result so the agent self-corrects against compiler/LSP output
- Diagnostics are filtered to severity===1 (ERROR only; WARN/INFO/HINT dropped) and capped at MAX_PER_FILE=20 with an '...and N more' suffix — deliberate signal-vs-noise trimming to protect the context window (lsp/diagnostic.ts)
- Auto-format on write: Format.file(filePath) runs a formatter after each edit, normalizing the diff
- Permission gate per tool call: allow / ask / deny modes with wildcard patterns in opencode.json (permission.ts); edits call ctx.ask({permission:'edit', patterns:[...]}) before writing
- Plan agent (read-only, no file mutation) vs Build agent split — same project context, enforced read-only mode for reasoning before changes
- NO test/CI execution gate, NO security/SAST scan, NO semantic-diff, NO trial-merge/conflict check, NO review-heuristic scoring, NO 'what to review' ranking — these do not exist in the codebase
- GitHub Action (mention-triggered): reads full PR/issue thread incl. reviews + review comments + diff, checks out local or fork branch, runs a chat, and if the branch is dirty commits & pushes changes back and updates the comment — augmentation, not analysis-scored gating

**Merge gate:** There is effectively NO merge/approval/verification gate. opencode is an execution substrate, not a gate. The GitHub Action (`github/action.yml`, `github/index.ts`) is invoked only on explicit `/oc` or `/opencode` mentions in issues, PR comments, or PR review-comment lines; on a PR it fetches PR data (comments/reviews/review-comments), checks out the head branch (local vs fork path), runs the agent, pushes any resulting commits, and posts a summary comment. It does NOT set commit statuses/required checks, does NOT block or perform merges, and computes no approval/trust score. Merge/branch-protection is delegated entirely to GitHub. The only 'verification' primitives in-product are the LSP-diagnostics self-correction loop, formatter-on-write, and the human permission prompt (ask/deny). Undo/rollback is handled by the shadow-git snapshot (revert/restore), not by a gate.

**Lessons for Recoder:**
- Adopt opencode's post-edit LSP diagnostics feedback loop as a deterministic, model-free Checks signal: run LSP touchFile+diagnostics on every converged/edited file and surface the ERROR-only, capped list. Recoder can go further and compute a 'diagnostics delta' (errors introduced by a candidate merge vs base) as a first-class readiness signal — grounded in compiler output, not model guessing
- Steal the shadow-git snapshot trick (separate --git-dir + objects/info/alternates seeded from the source repo, index reuse) for cheap per-run checkpoint/diff/revert and for staging convergence trial-merges on huge repos without polluting the user's repo or paying rehash cost (snapshot/index.ts)
- Use LSP references/callHierarchy/workspaceSymbol as a live blast-radius signal for the Checks surface instead of (or before) building an embeddings index — always fresh, language-accurate, zero index-staleness; ideal input to Recoder's open-work / 'what a merge touches' signal
- Copy the diagnostics filtering discipline: severity===1 only + MAX_PER_FILE=20 cap. A Checks surface must rank and truncate to high-severity signal or it becomes noise
- Formatter-on-write before convergence reduces spurious diff/merge conflicts between parallel worktree runs — normalize formatting on every agent edit so convergence conflicts are semantic, not whitespace
- opencode has NO merge gate, NO trial-merge, NO convergence-trust, NO test/security gate — this is precisely Recoder's differentiation. Position opencode as a runnable substrate UNDER Recoder's gate (it already emits worktrees + snapshots + LSP diagnostics Recoder can ingest as evidence), and make mergeability trial-merge + convergence-trust + a real Checks/merge gate the value Recoder adds on top
- Mirror the Plan(read-only)/Build split onto Recoder's advisory('warn') vs blocking('block') merge-trust modes — read-only agents still get full context, matching Recoder's subagent-for-investigation policy

### GitHub Copilot code review
*AI-PR-review-bot* — closed-source

**Ingestion:** Closed-source, runs entirely inside GitHub's infrastructure. As of the March 5, 2026 rewrite, it is an "agentic tool-calling" architecture: each review spins up an EPHEMERAL GitHub Actions environment (same substrate as the Copilot cloud/coding agent; GitHub-hosted runners by default, larger runners or self-hosted runners optional) and the review agent actively explores the repo with tools rather than just reading the diff. Its structural index is GitHub's internal "Code Graph," which lets the agent pull related files, directory structure, symbol references and cross-file dependencies as needed instead of only the changed lines. Context is bounded by the model context window (~128K-272K tokens cited) and a per-review time budget (~30s target), so large PRs / deep monorepos degrade. It also ingests repo instruction files (.github/copilot-instructions.md, path-scoped .github/instructions/**/*.instructions.md, AGENTS.md), PR metadata (issue/incident IDs in the description), and can call configured MCP servers/agent skills during review ("Allow Copilot to use MCP tools when reviewing pull requests" is on by default). It does NOT bundle its own deterministic linters — analysis is LLM-driven, though the ephemeral env can run tools/linters/tests and it integrates with GitHub-native static analysis (CodeQL).

**Checks run:**
- Logic/correctness bugs: operator confusion, off-by-one, edge cases, unclear/complex logic (agent traces cross-file context via Code Graph before commenting)
- Security vulnerabilities: LLM pattern flags plus integration with GitHub code scanning / CodeQL (SQL injection, XSS - coverage varies; one academic test found it missed seeded vulns)
- Style/readability inconsistencies and maintainability patterns (LLM-based, NOT deterministic linters like ESLint/Pylint/RuboCop; can invoke ESLint/PMD/CodeQL in the ephemeral env)
- Cross-service / architectural-fit review at higher effort ('Balanced' effort level does deeper analysis of complex logic, security-sensitive and cross-service changes)
- Custom-rule enforcement from copilot-instructions.md / AGENTS.md / path-scoped instructions - team conventions read from the PR HEAD branch
- Inline suggested fixes attached to logical code ranges (not just single lines), one-click acceptable; findings deduplicated across files to cut noise
- PR summary generation (draft description + list of affected files) to give human reviewers context
- MCP tool / agent-skill calls for specialized project-specific context during review

**Merge gate:** Advisory only — deliberately NOT a merge gate. Copilot ALWAYS leaves a "Comment" review, never "Approve" or "Request changes," so it cannot satisfy branch-protection required-reviewer rules and cannot block or approve a merge on its own. Enablement is via rulesets ("Automatically request Copilot code review" branch rule, at repo or org level, with optional "Review new pushes" and "Review draft PRs"), which only auto-requests a review; it does not create a pass/fail status check. Practitioner consensus: pair Copilot (explains problems) with GitHub Actions status checks + required human reviews + CODEOWNERS (prove problems) to actually gate merges. The separate Copilot CODING agent's PRs ARE subject to branch protection/required checks, cannot self-mark ready, cannot self-approve/merge, and the prompting user is blocked from approving to preserve independent review. Handoff model: replying "@copilot" on a comment makes the coding agent implement the fix as a STACKED PR (human approval still mandatory; never auto-merges). Review sessions are auditable via session logs showing which tools/skills/MCP servers ran.

**Lessons for Recoder:**
- Separate 'explain' from 'prove': Copilot's comment-only stance is a warning, not a feature to copy blindly — Recoder's convergence layer should keep emitting hard pass/fail signals (trial-merge, tests, trust score) that CAN gate, unlike Copilot which relies on other tools. Position this as our advantage.
- Adopt a Code-Graph-style structural index for review context: don't review the diff in isolation — resolve related files, symbol references and cross-file/cross-service blast radius before scoring merge readiness. Copilot's biggest quality jump came from moving diff-only -> agentic context-gathering.
- Run checks in an ephemeral, reproducible sandbox that can execute the repo's OWN linters/tests (deterministic), then layer LLM semantic review on top. Copilot's documented gap is having NO deterministic linters (pure LLM) — Recoder can beat it by combining deterministic tool output + LLM into the trust score (CodeRabbit's 40+ linter dual-layer is cited as superior).
- Read team convention files as first-class review inputs (copilot-instructions.md / AGENTS.md / path-scoped instructions) from the PR HEAD branch — make Recoder's Checks surface honor repo-local policy, not just generic heuristics.
- Deduplicate findings across files and cap by an explicit time/context budget; surface which tools/MCP servers ran as an auditable session log — matches Recoder's evidence-backed, truthful-health philosophy.
- Expose an explicit effort level (fast vs 'Balanced' deep cross-service analysis) so reviewers can trade latency for depth on risky merges.
- Handle large-PR degradation honestly: Copilot's success drops sharply above ~50 lines / in monorepos due to context limits. Recoder should chunk/rank by blast radius and clearly flag when a merge exceeds a confidence budget rather than emit false confidence.
- **Shipped 2026-08-30:** each current finding can start a head-pinned fix worktree, reuse an active attempt, retry a failed attempt, and open the resulting Wave diff. The agent cannot push, merge, publish, or approve its own work.
- Make auto-published comments high-precision: estimates say 29-45% of AI review suggestions contain issues, so Recoder should gate low-confidence findings behind the trust score / advisory tier rather than posting everything as authoritative.

### Graphite Diamond (Graphite AI Reviews + Graphite Merge Queue)
*AI-PR-review-bot + stacked-PR merge queue (merge-gating platform)* — closed-source

**Ingestion:** Closed-source; details are from Graphite/Claude/Braintrust case studies and docs, not code. Diamond is "codebase-aware": it does NOT limit itself to the PR diff — it pulls context from across the repo. Public "how it works" guides describe the generic pipeline as clone-repo-or-fetch-diff, AST parsing (tree representation of variables/functions/loops), then feeding code chunks + diff into a hosted LLM (they chose Claude 3.5 Sonnet after benchmarking 500 PRs). Graphite has NOT publicly confirmed embeddings, a semantic/vector index, a symbol/call graph, LSP, or blast-radius analysis — "context gathered directly from your codebase" is the only stated mechanism, so the exact retrieval method (agentic grep/file-reads vs. embeddings) is undisclosed. Custom rules add explicit context: file-based rules use glob patterns (docs/coding-style.md, CONTRIBUTING.md, .github/rules/*.md) whose file contents Diamond reads from the repo at review time (large files truncated; too many files degrades quality) — deterministic file-injection rather than inferred retrieval.

**Checks run:**
- Logic bugs / logical errors (e.g. improperly structured conditions, wrong comparison operators, unintentional control-flow bypasses)
- Security vulnerabilities (SQL injection, insecure token/secret logging, unsafe platform-specific code; OWASP template rules)
- Performance bottlenecks (e.g. premature await inside Promise.all, N+1-style issues)
- Copy-paste mistakes and function parameter-ordering errors
- Edge cases and API-misuse bugs (e.g. reusing one React ref across multiple DOM nodes breaking IntersectionObserver)
- Style / naming / consistency vs. the rest of the codebase (detects inconsistencies against existing repo conventions)
- Documentation gaps and irrelevant/mislabeled doc comments
- Accidentally committed code / debug leftovers
- Custom-rule violations: plain-language custom prompts, regex rules, and imported style guides (Airbnb JS, Google Java/TS/Go, PEP8, accessibility, OWASP)
- MERGE QUEUE (separate from Diamond): trial rebase onto latest trunk, real CI/required-checks execution, and mergeability/conflict detection at merge time

**Merge gate:** Two DISTINCT gates that are not tightly coupled. (1) Diamond posts advisory review comments via GitHub's Review API (inline, like a human) with one-click suggested fixes — it is explicitly positioned as a co-reviewer that complements, never blocks/replaces, human review; comments can also be surfaced as a required status check but the product philosophy is high-signal advice, not hard gating. (2) The Graphite Merge Queue is the actual merge gate: a PR (or whole stack) enters the queue, is rebased on latest trunk, required CI checks run, and it merges only if green; conflict or failing test => ejected from queue with an explanatory PR comment, keeping main always-deployable. It is stack-aware: validates entire PR stacks in parallel and uses fast-forward merge to avoid re-running CI on already-validated changes (batched/optimistic merges, ~1.5x faster, p75 -26%). Enforced via GitHub branch protection (must disable GitHub's native merge queue; if not enforced, devs can bypass via GitHub directly).

**Lessons for Recoder:**
- Split the ADVISORY reviewer from the HARD merge gate the way Graphite does: Diamond gives high-signal review comments while the Merge Queue is the true gate. Recoder's convergence layer should keep the trust score / review-flags as advisory signals and make the trial-merge + real-CI-green the actual merge decision — matches our warn-vs-block trust gate default.
- Adopt a precision-over-recall posture with a published false-positive budget: Graphite's sub-3% FP claim (at the cost of recall) is a marketing and trust asset. Recoder's convergence-trust reviewFlags should be calibrated + labeled 'high-signal', and we should track our own FP rate as a truthful health metric.
- Build a multi-layer verification chain before surfacing a merge verdict: voting + chain-of-reasoning + self-critique. Our convergence trust score could ensemble multiple independent checks (each run's readiness signal, a cross-run consistency vote, an adversarial self-critique pass) rather than a single LLM judgment.
- Ground trust in an accept/reject FEEDBACK FLYWHEEL: instrument whether a developer accepted the converged merge / each contested-file pick, and feed that back as eval ground truth (Braintrust-style: line-range validity + semantic-similarity regression + binary accept). Recoder already has the Checks surface + merge outcome view — wire per-flag accept/reject telemetry into it.
- Deterministic rule-context injection via glob patterns: Diamond reads CONTRIBUTING.md / docs/*.md / .github/rules/*.md as explicit review context. Recoder should let a task spec point at repo doc globs whose contents are injected into the reviewing agent, with truncation limits — cheaper and more auditable than pure inferred retrieval.
- Stack-aware, CI-reuse merging: fast-forward merge that avoids re-running CI on already-validated changes is a direct win for our parallel-worktree model — when N runs converge, reuse each run's already-green verification instead of re-verifying the merged result from scratch where the change set is identical.
- Eject-with-explanation on gate failure: the queue removes a failing PR and leaves a comment on exactly what failed. Recoder's merge gate should always emit a truthful, evidence-linked rejection reason (which check/conflict/trust-flag) rather than a generic fail — aligns with our 'never fake success' rule.
- Codebase-relative consistency checks: Diamond flags code that diverges from existing repo conventions. Recoder could add a 'consistency vs. main' signal to convergence trust — does the merged result match established patterns/APIs already in the trunk.

### Baz (baz.ai, formerly baz.co / getbaz)
*AI-PR-review-bot + autonomous merge-gate (Engineering Review Platform)* — closed-source

**Ingestion:** Whole-repository (not per-file) ingestion. The codebase is split into "indexable units," and embeddings + similarity measures are used to retrieve relevant code and tests for the change being reviewed (semantic/RAG-style retrieval over the repo index, plus cross-repo links). Diffing is AST/semantic, not line-based: Baz leverages Difftastic, which parses code with Tree-sitter, then diffs the Abstract Syntax Tree (nodes = syntax elements like functions/variables/expressions; edges = structure/relationships) to find added/removed/modified nodes precisely across many languages. On top of static retrieval, agents do optional runtime/behavioral inspection — "read and interpret code changes as if they are already running" for a downstream outlook, and the Spec Reviewer uses Amazon Bedrock AgentCore secure browser automation to drive a running preview app/sandbox and validate behavior against requirements. Context assembled per PR: PR diff, PR description, ticket text/attachments (Jira), design files, CI status, review findings, repo index, related files, git history, package/dependency metadata, cross-repo consumer references, production telemetry (Datadog), and org guidelines/instruction files (AGENTS.md, CLAUDE.md, Cursor rules, Skills). Closed-source, so exact chunking/embedding model and index store are not disclosed.

**Checks run:**
- Semantic AST diff (Difftastic + Tree-sitter) to detect meaningful changes and cut diff noise / false positives
- Breaking-changes reviewer: flags API/contract/type surface changes ONLY with direct evidence a real consumer or contract is affected (ties change to dependent consumers)
- Type-safety reviewer: type changes that cause runtime/integration breaks across module boundaries
- Logic-correctness reviewer: flawed conditionals, edge cases, unintended side effects, incomplete impls — provides execution traces for failing paths, prioritizes concrete reproducible issues over hypotheticals
- Spec reviewer: extracts explicit requirements from ticket/design, validates the running implementation, returns met / partially-met / not-met
- Advanced security reviewer: exploitable behavior across authn/authz, input handling, data exposure, dependencies, insecure defaults/flows — requires evidence from system behavior, not generic scanner output; plus common-patterns reviewer for secrets/PII/injection with exact locations
- Guidelines enforcer: converts org instruction files into coding guidelines and applies ONLY the guidelines whose scope matches the changed file directories; cites the guideline source; skipped entirely if no in-scope guideline exists
- Code-quality flows: clarity/naming/typos, duplication, idiomatic usage, style/clutter, conciseness, test quality
- SRE reviewer: reliability (retries, error handling), performance (inefficient queries), observability gaps — cross-referenced with prod telemetry
- CI status + whether Baz's own findings on the PR are still unresolved
- Blast-radius / change-impact assessment: does the change touch core logic; how risky within the repo; prior related commits/git history
- Business-impact and file-count/severity thresholds (deterministic bars, e.g. <50 files, no HIGH-severity finding)
- Post-processing: dedup + merge related comments and validate each finding is meaningful/actionable before surfacing; adaptivity from team's historical addressed-rate and past reviews

**Merge gate:** Dedicated autonomous "Merger" agent runs on every new commit/PR for configured repos and returns one of three verdicts: MERGE / REJECT / ESCALATE, labeling the PR and optionally posting a rationale comment. Governed by per-repo Merger RULES that combine (a) DETERMINISTIC bars a PR must pass (e.g. fewer than 50 files changed, no HIGH-severity finding, required CI checks green, all Baz findings resolved, auto-approve conditions) with (b) a textual/natural-language guideline the AI uses for judgment. It weighs CI state + unresolved findings, diff riskiness + git history, org guidelines/auto-approve rules, and blast radius. ESCALATION is the explicit safety valve: failed/pending CI, open critical issues, or high business impact always routes to a human. When a rule is configured to act autonomously AND the verdict is 'merge,' Merger merges the PR itself; otherwise it just leaves the verdict + label for a human. A Merger Stats dashboard tracks evaluated-PR volume, ready-to-merge rate, merged-without-human rate, outcome breakdown, and throughput over time. Findings surface as PR comments + CI check results; suggested fixes (Fixer agent) can be committed directly to the PR.

**Lessons for Recoder:**
- Adopt a 3-way merge verdict (merge / reject / ESCALATE) instead of a binary gate — an explicit escalate-to-human state for uncertain or high-blast-radius changes maps directly onto Recoder's convergence-trust warn/block model and makes 'unsure' truthful rather than a forced pass/fail.
- Make the merge gate a hybrid of DETERMINISTIC bars + a natural-language guideline: hard bars (files-changed cap, no HIGH-severity finding, CI green, all findings resolved) short-circuit cheaply, then an LLM judges the residual. Recoder's Checks surface + convergence-trust score could expose these bars as named, individually-passing/failing rows.
- Compute an explicit BLAST-RADIUS / change-impact signal (touches core logic? which consumers depend on the changed contract? prior related commits) and feed it into the trust score — this is a concrete 'open-work / risk' signal beyond mergeability that Recoder's readiness signals could add.
- Use semantic AST diff (Difftastic + Tree-sitter) for the compare view and contested-file picker instead of line diffs — cuts convergence noise and lets the fan-out picker reason about meaningful node-level changes, improving 'what to review' surfacing.
- Split review into many single-concern flows over ONE shared repo index, then dedup/merge/validate findings before surfacing — Recoder could gate each finding on 'is it actionable + has direct evidence' to avoid the AI-review noise that erodes trust.
- Gate breaking-change and security findings on DIRECT evidence (a real affected consumer/contract/behavior), not hypotheticals — a concrete rule Recoder can apply so trust reviewFlags stay high-signal.
- Ingest the WHOLE repo into indexable units with embedding+similarity retrieval of the relevant code AND tests for each change, plus cross-repo consumer references — richer than diff-only context; aligns with Recoder's retrieval_ingest/retrieval_search MCP tools as the evidence backbone for merge decisions.
- Enforce the repo's own instruction files (AGENTS.md/CLAUDE.md/rules) as scope-matched, source-cited guidelines applied only to touched directories — Recoder already has these files; turning them into an auto-checked, cited merge signal is low-cost and on-brand.
- Ship a Merger-style AUTONOMY dashboard (evaluated PRs, ready-to-merge rate, merged-without-human rate, outcome breakdown) so the convergence layer's trustworthiness is measurable and truthful over time.
- Optional runtime/behavioral verification of a running preview (spec met/partially-met/not-met) as an evidence artifact — complements Recoder's preview_health/browser_verify tools and strengthens evidence-backed merges.

### Ellipsis (ellipsis.dev, YC W24)
*AI-PR-review-bot* — closed-source

**Ingestion:** Closed-source. On PR open/ready, a GitHub App webhook is delivered via Hookdeck -> FastAPI -> a Hatchet workflow queue; the workflow git-clones the repo and runs the review agent. Repo indexing is a fresh, incremental vector index kept in Turbopuffer (no customer code stored — only embeddings + obfuscated location metadata). Dual indexing: (a) tree-sitter parses the AST into high-level chunks (functions/classes) for precise code lookup, and (b) an LLM-generated natural-language summary is embedded per file for higher-level questions. Incremental sync uses the SHA of each chunk as its vector ID: on each commit it fetches existing IDs, diffs new vs existing, deletes stale IDs, and only embeds/upserts changed chunks — so most commits re-sync in ~a couple seconds. IDE-grade navigation is added by side-caring an lsproxy container (from Agentic Labs) on Modal, giving agents LSP go-to-definition / find-all-references; because LLMs are bad at column numbers, agents pass a symbol NAME and lsproxy fuzzy-matches to the nearest symbol. After vector search, an LLM binary relevance classifier ('RAG+') drops irrelevant hits to avoid context pollution. Autofix/code-generation runs in an isolated Docker/cloud sandbox that can compile and run tests.

**Checks run:**
- Multi-agent design: instead of one giant prompt, DOZENS of small independently-benchmarked 'Comment Generators' run in PARALLEL, each hunting a distinct issue class (logical bugs, antipatterns, duplicated code, custom-rule/style-guide violations)
- Natural-language custom rules in ellipsis.yaml/code_review.yaml (e.g. 'new code must have unit tests', 'no secrets/credentials in code', 'code should be DRY', 'follow Single Responsibility') — no rule DSL; rules can be authored in UI, INFERRED from historical comments, or extracted from existing style-guide files in the repo
- Every finding must carry Evidence (links to concrete code snippets) so downstream filters can verify it
- Multistage Filtering Pipeline to kill false positives: (1) dedup across overlapping generators, (2) confidence-threshold filter (per-comment confidence score; default ~0.7, examples use 0.85, raise to 0.9 if noisy), (3) hallucination/logical-correctness check that uses the attached Evidence to reject ungrounded comments, (4) comment-editing pass that fixes line numbers and inline code suggestions
- Learns from feedback WITHOUT fine-tuning: thumbs-up/down and user replies are retrieved via embedding search over similar past comments to suppress comment types the team ignores
- PR summary generation (auto_summarize_pr) and 'quiet mode' that suppresses 'LGTM' when there are no findings
- Autofix path additionally verifies by compiling and running tests inside a Docker sandbox before delivering a change (comment-to-commit), unlike IDE/chat tools that never run the code

**Merge gate:** Advisory-by-default inline review, NOT a hard blocker out of the box. One org-wide toggle turns review on for every PR; findings post as inline GitHub review comments as commits land. Review is INCREMENTAL — already-reviewed lines are never commented twice; only new commits are analyzed on each push. Scope/filter by repo, branch, path, author, and draft status; bot PRs are reviewed except dependabot/renovate (cost control). Optional enable_approve_prs lets Ellipsis post an APPROVE review. To make it a true merge gate you rely on GitHub branch-protection marking the Ellipsis check as required (Ellipsis itself does not document a native block_prs field). Autofix/code-gen 'never commits without explicit permission' and can be configured to raise a side-PR so its changes are auditable. Newer 'agents-as-code' model: agents are YAML on the default branch (merge to update, no deploy), controllable from dashboard/CLI/REST with full inspectable session history.

**Lessons for Recoder:**
- Treat 'confidence' as a first-class, tunable dial on the Checks surface: score every readiness/trust signal and expose a per-repo confidence_threshold so teams trade noise vs recall — mirror Ellipsis's 0.7/0.85/0.9 knob for our convergence-trust flags
- Require EVIDENCE on every check/finding (link to the exact code snippet/line) and run a hallucination/grounding filter that drops any signal whose evidence doesn't verify — directly strengthens our 'never imply success without evidence' rule and the trust reviewFlags
- Decompose our repo/PR analysis into many small, independently-benchmarkable check generators run in parallel (bug, dup-code, style-rule, test-coverage, secret) instead of one big prompt; each becomes a benchmarkable eval and a labeled Checks-tab row
- Add cheap incremental indexing keyed by chunk SHA (tree-sitter AST chunks + per-file LLM summaries) so re-indexing a worktree after each agent commit costs ~seconds, not a full re-embed — useful for the fan-out where N worktrees each mutate the same base
- Give the convergence/merge reviewer LSP-grade navigation (go-to-definition/find-references via an lsproxy-style sidecar) so mergeability/blast-radius reasoning follows call graphs beyond the raw diff, and use symbol-name fuzzy matching instead of trusting LLM line/column numbers
- Learn from human merge decisions via embedding search over past accepted/dismissed flags (thumbs-up/down) to auto-suppress low-value signals — no fine-tuning needed
- Incremental review discipline: never re-flag already-reviewed lines across pushes — apply the same to our Checks surface so trust flags only re-evaluate changed hunks
- Verify autofixes by compiling + running tests in an isolated sandbox before surfacing them as merge-ready — matches our 'trial-merge + evidence' gate and prevents proposing untested convergence merges
- Keep the gate advisory-first with an explicit opt-in to blocking (branch-protection style) plus an optional auto-approve — our merge trust gate's off/warn/block ladder is the right shape; Ellipsis validates warn-by-default
